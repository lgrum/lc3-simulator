Calculator Module Guide

Each group writes one or more modules: .asm files with the calculator functions you were assigned. The professors' main program calls them. You don't choose where your code goes in memory; the linker places it.

Writing a module x0000 + base

  • The file name is the module name. trig.asm is the module trig. Use letters, digits and _ only, starting with a letter or _. No -.
  • .ORIG is optional and ignored in modules. The linker places your code after main and the other modules. Only the entry file's .ORIG counts.
  • Your labels are yours. LOOP in your file never clashes with another group's LOOP.
  • Keep using PC-relative instructions inside your file as usual. They still work after the linker moves your code.

trig.asm · group 7

; SIN: R0 = angle in radians, Q14
;      returns R0 = sin(angle), Q14
SIN     ADD  R6, R6, #-2      ; push R1 and R2 (see convention)
        STR  R1, R6, #0
        STR  R2, R6, #1
        ; ... your algorithm ...
        LDR  R1, R6, #0       ; pop them from the same slots
        LDR  R2, R6, #1
        ADD  R6, R6, #2       ; R6 is back to its value on entry
        RET
        .END

Calling a label in another file

Declare it with .EXTERNAL, written as MODULE-LABEL: the file name, a -, then the label. The module part ignores case; the label part doesn't.

main.asm

        .ORIG x3000
        .EXTERNAL TRIG-SIN    ; label SIN in trig.asm
        LD   R0, ANGLE
        LD   R5, SIN_PTR      ; full 16-bit address of TRIG-SIN
        JSRR R5
        HALT
ANGLE   .FILL x1922           ; π/8 ≈ 0.3927 in Q14
SIN_PTR .FILL TRIG-SIN
        .END

Use .FILL + JSRR for every call to another file. JSR only reaches ±1024 words, and with 20+ modules laid end to end most targets are farther away than that.

Where you use an external label Allowed?
.FILL TRIG-SIN Always
JSR, BR, LD, LDI, ST, STI, LEA Only if in range; otherwise a link error tells you to use .FILL + JSRR
TRAP, LDR/STR offsets Never

What you may import

  • Labels from your own group's other modules.
  • Not your own file (just use the label), not main, not the OS (use TRAP), and not other groups' modules.

Calling convention

Every module follows the same rules, so main can call any group's code the same way.

R0, R1, R2Arguments
R0Result
R1–R5Preserved by the subroutine
R6Stack pointer. It must hold the same value on return as on entry.
R7Return address. Push it before calling another subroutine.
  • Save registers on the stack, through R6. R6 is the LC-3's conventional stack pointer, and the operating system treats it that way: every TRAP switches to the system stack and gives you your R6 back untouched on return. Don't reserve .BLKW areas just to store registers.
  • The stack grows toward lower addresses. To push, subtract from R6 and write with STR; to pop, read with LDR and add to R6. Pop everything you pushed before RET.
  • Don't initialize R6 or use it as a general-purpose register. The simulator already points it at the user stack when it loads the program.
  • There's no common number format. Each function picks the Q format it needs (for example Q14 for SIN/COS, Q3 or Q4 for EXP). Write it in a comment above the label. Callers convert their arguments before calling.

Calling another subroutine from a subroutine

        ADD  R6, R6, #-1      ; push R7: JSRR is about to overwrite it
        STR  R7, R6, #0
        JSRR R4               ; R4 = address loaded with .FILL (and pushed on entry)
        LDR  R7, R6, #0       ; pop R7
        ADD  R6, R6, #1
        RET

Testing locally

You can't see main or other groups' code, so test with your own small main.asm.

  1. Create your module files and a main.asm in the file sidebar.
  2. Right-click main.asm and choose Set as entry.
  3. Click Assemble. Errors from every file appear in the Problems tab.
  4. Open the Link map tab to see where each module landed in memory.
  5. Set breakpoints in any file. The editor follows the PC into whichever file it's in.

Your files stay in this browser until you publish. Download the project as a .zip from the sidebar to move it to another computer.

Publishing

  1. Log in with your group number and the password or token your professor gave you.
  2. Open the module file and click Publish. The first publish of a file name creates that module; later publishes add versions (v1, v2, ...).
  3. The server assembles your file first. Code with errors isn't published.
  • The professors always use your latest published version. Work in progress stays private until you publish.
  • Other groups never see your code. Professors can.
  • A module can't be renamed. Publishing under a different file name creates a new module.
  • My modules lists your versions. You can download or restore any of them.

The professors refer to group 7's trig module as g7_trig, so their main says .EXTERNAL G7_TRIG-SIN. You don't write that form yourself.
